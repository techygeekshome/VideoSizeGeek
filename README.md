Type 10 MB, get a video that fits Discord's free upload cap. Type 25 MB for Gmail, 16 for
WhatsApp, or a number of your own. VideoSizeGeek works out the bitrate that actually lands there,
encodes it in two passes so the size is hit rather than guessed at, and tells you before it
starts if the target is too small for the clip to still look right.

## Download

**[Download the latest release](https://github.com/techygeekshome/VideoSizeGeek/releases/latest)**, or read about it on the
[product page](https://techygeekshome.info/videosizegeek/).

Two files on every release, both checked against `SHA256SUMS.txt`:

- **VideoSizeGeekSetup.exe**: installer, no admin rights needed, installs for your account only.
- **VideoSizeGeek-portable.exe**: no installer, just run it.

VideoSizeGeek is not code signed yet, so Windows SmartScreen will warn on first run. [Why that
happens, and how to check the download is genuine.](https://techygeekshome.info/why-windows-warns-about-this-download/)

## What it does

- **Named presets**: Discord's 10 MB free cap, Discord Nitro's 500 MB, Gmail's 25 MB attachment
  limit, WhatsApp's 16 MB, X's 512 MB, or type your own target in MB.
- **Two-pass encoding**, so the output lands at or under the target instead of somewhere near
  it. If the first pass overshoots, it corrects once and re-encodes rather than shipping a file
  that is still too big.
- **Says so before it starts** if the target is too small for the clip to hold a watchable
  bitrate, rather than quietly handing back a blocky mess.
- **Never touches the original.** The output is always a new file next to the source.

## Requirements

- Windows 10 or 11, 64-bit.
- **ffmpeg**, installed separately. VideoSizeGeek does not bundle it and will not silently download
  and run a copy on your behalf; the app tells you where to get it
  ([gyan.dev's builds](https://www.gyan.dev/ffmpeg/builds/)) the first time it can't find one.
  Put `ffmpeg.exe` and `ffprobe.exe` somewhere on your PATH and restart VideoSizeGeek.

## Why this exists

HandBrake has turned this feature down twice, on the record ([issue
#2483](https://github.com/HandBrake/HandBrake/issues/2483), [issue
#4622](https://github.com/HandBrake/HandBrake/issues/4622)), both closed as out of scope. Every
tool that does it now is a web upload competing for "shrink video to 10MB" in search results,
which means sending the clip to a stranger's server to find out if it fits. VideoSizeGeek does the
same arithmetic ffmpeg has always been capable of, locally, with the honesty about quality that
a web tool has no reason to volunteer.

## Building it yourself

```
dotnet build VideoSizeGeek.sln -c Release
dotnet run --project tests/VideoSizeGeek.Tests -c Release
```

The test project includes a real two-pass encode against a synthetic clip generated by ffmpeg
itself, so it needs ffmpeg on PATH to run that part; everything else runs anywhere .NET 8 does.
